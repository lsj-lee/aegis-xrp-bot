# AEGIS System Evolution Briefing
## 1. 사유 (Reason)
기존 `aegis_main_system.py` 파일은 시스템의 핵심 파이프라인을 조율하는 중요한 역할을 수행하고 있었습니다. 그러나 로깅 방식이 `print`문과 단순한 파일 쓰기 함수(`print_status`)에 의존하여, 다음과 같은 한계가 있었습니다:
*   **일관성 부족**: 다양한 `print` 문과 `print_status` 함수가 혼재되어 출력 형식이 일정하지 않았습니다.
*   **유연성 부족**: 로그 레벨(정보, 경고, 오류 등)을 구분하여 관리하거나, 콘솔 출력과 파일 출력의 상세 수준을 다르게 설정하는 것이 어려웠습니다.
*   **확장성 부족**: 향후 로그를 외부 시스템(예: ELK 스택, 클라우드 로깅 서비스)으로 전송하는 등의 기능 추가 시 많은 수정이 필요했습니다.
*   **예외 처리 미흡**: `print_status`의 파일 쓰기 예외 처리가 너무 광범위하여 잠재적인 문제를 숨길 수 있었습니다.
*   **디버깅 어려움**: 문제 발생 시 어느 부분에서 어떤 레벨의 메시지가 발생했는지 명확하게 추적하기 어려웠습니다.

또한, `subprocess` 명령어를 문자열로 넘기는 방식(예: `os.system` 또는 `subprocess.run(shell=True)`)은 보안 및 정확도 면에서 리스트 형태로 넘기는 방식보다 취약할 수 있어 개선의 여지가 있었습니다.

## 2. 변경점 (Changes)
1.  **로깅 모듈 도입**: Python의 표준 `logging` 모듈을 전면적으로 도입했습니다.
    *   `logging` 모듈을 임포트하고, `PROJECT_ROOT` 하위에 `aegis_system.log` 파일을 생성하도록 설정했습니다.
    *   콘솔(stdout)과 파일 모두에 로그를 기록하는 핸들러를 구성하고, 통일된 형식의 `Formatter`를 적용했습니다.
    *   모든 `print` 문과 기존 `print_status` 함수 호출을 `logger.info()`, `logger.warning()`, `logger.error()`, `logger.critical()` 등 적절한 로그 레벨 함수로 대체했습니다.
2.  **`print_status` 함수 제거**: 로깅 모듈 도입으로 인해 더 이상 필요 없어진 `print_status` 함수를 제거했습니다.
3.  **`MAC_SLEEP_COMMAND` 형식 변경**: `subprocess.run` 호출 시 `pmset sleepnow` 명령어를 단일 문자열이 아닌 리스트 `["pmset", "sleepnow"]` 형태로 변경하여, `shell=False` (기본값)로 실행될 때 더욱 안전하고 명확하게 명령어를 전달하도록 했습니다. 이에 따라 `--enable-sleep` 인자의 `--help` 메시지도 업데이트되었습니다.
4.  **최상위 예외 처리 추가**: `if __name__ == "__main__":` 블록에서 `run_pipeline` 호출을 `try...except` 블록으로 감싸, 파이프라인 실행 중 발생할 수 있는 예상치 못한 최상위 예외를 `logger.critical`로 기록하고 프로그램이 안전하게 종료되도록 했습니다 (`exc_info=True`로 트레이스백 포함).
5.  **오류 메시지 명확화**: `subprocess.run`에서 오류 발생 시 `stdout`과 `stderr`의 출력을 좀 더 명확하게 구분하여 기록하도록 개선했습니다.

## 3. 기대 효과 (Expected Effect)
*   **향상된 가독성 및 유지보수성**: 모든 시스템 메시지가 통일된 로깅 방식으로 출력되어 로그를 읽고 이해하기 쉬워집니다. 문제 발생 시 관련 로그를 빠르게 찾아낼 수 있어 유지보수가 용이해집니다.
*   **강화된 디버깅 능력**: 로그 레벨을 통해 중요도에 따라 메시지를 필터링할 수 있으며, 오류 발생 시 상세한 트레이스백(traceback)을 자동으로 기록하여 원인 분석 시간이 단축됩니다.
*   **안정성 및 신뢰성 증대**: `logging` 모듈의 견고한 파일 핸들링은 로그 파일 작성 중 발생하는 예외를 더 안정적으로 처리합니다. `subprocess` 명령어의 리스트 형식 변경은 잠재적인 셸 인젝션 공격 위험을 줄이고 명령 실행의 정확도를 높입니다.
*   **확장성 증대**: 향후 시스템 요구사항이 변경되어 다양한 로깅 핸들러(네트워크, 데이터베이스 등)를 추가하거나, 로깅 설정을 동적으로 변경해야 할 때 유연하게 대응할 수 있습니다.
*   **일관된 사용자 경험**: 사용자에게 제공되는 모든 시스템 메시지가 통일된 형식으로 출력되어 전문성과 안정감을 더합니다.
*   **조용한 성공**: 성공적인 파이프라인 실행 시에는 필수 정보만 기록하고, 상세한 서브프로세스 출력은 필요에 따라 `DEBUG` 레벨로 전환할 수 있는 기반을 마련하여 로그의 노이즈를 줄였습니다.
