# AEGIS System Evolution Briefing
## 1. 사유 (Reason)
현재 'aegis_main_system.py'는 AEGIS 시스템의 핵심 오케스트레이터로서 잘 작동하고 있습니다. 하지만 코드의 유지보수성, 안정성, 가독성을 더욱 향상시키고 미래 확장을 용이하게 하기 위해 몇 가지 개선이 필요했습니다. 특히, 시스템 명령어 실행 방식의 통일성과 오류 메시지의 일관성 확보가 중요했습니다.

## 2. 변경점 (Changes)
1.  **`subprocess.run` 활용 강화**:
    *   기존 `os.system(MAC_SLEEP_COMMAND)`를 `subprocess.run` 기반의 헬퍼 함수로 변경했습니다. 이는 시스템 명령 실행에 대한 더 나은 제어, 오류 처리, 그리고 보안을 제공합니다.
    *   `MAC_SLEEP_COMMAND` 상수를 문자열에서 `["pmset", "sleepnow"]`와 같은 리스트 형태로 변경하여 `subprocess.run`의 권장 사용 방식에 따르도록 했습니다.
2.  **출력 로깅 일관성 확보 (`print_status` 도입)**:
    *   모든 `print()` 호출에 타임스탬프와 레벨(INFO, ERROR 등)을 포함하는 `print_status` 헬퍼 함수를 도입했습니다. 이를 통해 시스템 로그의 가독성이 향상되고, 향후 로깅 시스템으로의 전환이 용이해집니다.
3.  **코드 구조 및 초기화 강화**:
    *   `PYTHON_EXEC` (가상 환경 파이썬 실행기)의 유효성 검사를 `run_pipeline` 함수 초기에 한 번만 수행하도록 변경했습니다. 이는 각 파이프라인 단계에서 반복되는 검사를 제거하고, 문제가 있을 경우 더 일찍 종료하여 불필요한 작업 수행을 방지합니다.
    *   `check_pending_proposals` 함수 호출 시점을 초기 시스템 정보 출력 이후로 옮겨, 시작 메시지 흐름을 자연스럽게 만들었습니다.
    *   전체 스크립트 실행 로직을 `main()` 함수로 캡슐화하여 표준 Python 스크립트 구조를 따르도록 했습니다.
4.  **불필요한 `glob` import 제거**:
    *   `pathlib.Path.glob()`을 사용하므로 더 이상 필요 없는 `glob` 모듈 import를 제거했습니다.
5.  **인자 도움말 메시지 개선**:
    *   `--enable-sleep` 인자의 도움말 메시지에 실제 실행될 명령어(리스트 형태)를 반영하여 더 정확한 정보를 제공합니다.

## 3. 기대 효과 (Expected Effect)
*   **안정성 향상**: `os.system` 대신 `subprocess.run`을 사용하여 시스템 명령 실행 시 발생할 수 있는 잠재적 문제를 줄이고, 더 세밀한 오류 처리가 가능해집니다.
*   **가독성 및 유지보수성 증대**: `print_status` 함수를 통한 일관된 출력 형식은 로그를 이해하기 쉽게 만들고, `main()` 함수와 초기화 로직 개선은 코드 구조를 명확하게 하여 향후 기능 추가나 수정이 용이해집니다.
*   **성능 및 효율성 약간 개선**: `PYTHON_EXEC` 유효성 검사를 한 번만 수행함으로써 불필요한 파일 시스템 접근을 줄입니다.
*   **디버깅 용이성**: 모든 출력에 타임스탬프와 레벨이 포함되어 특정 시점의 시스템 상태 파악 및 문제 진단이 훨씬 쉬워집니다.
